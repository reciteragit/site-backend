# Class reminders, calendars and teacher-approved cancellation

Confirmed bookings queue reminders for both the student's email/timezone and the linked teacher account's email/timezone. Thresholds are actual elapsed 24 hours and 30 minutes before the UTC class start, including daylight-saving transitions. A booking made inside a threshold skips that reminder. Existing future confirmed bookings are discovered by the mail worker. Notices have a unique booking/recipient/kind key, database leases and provider idempotency keys; delivery failures remain retryable. Cancelled classes do not receive reminders. The 24-hour notice expires after a 30-minute delivery window, and the 30-minute notice expires at the class start, so stale reminders are not sent after their useful window.

The authenticated student requests cancellation from their class card at least 24 hours before start. The booking remains confirmed and blocks the slot while pending. An email asks the teacher to log in to their dashboard and approve or decline. Only the linked teacher account can decide, only before class starts, and a decided request cannot be reversed through replay. Approval marks the booking cancelled, releases the time and queues notifications to both participants. Declining leaves the class confirmed. Cancellation does **not** refund or alter the paid order; refunds/payment adjustments need separate handling. The backend enforces the deadline and ownership regardless of displayed buttons.

Class cards for both participants link to Google Calendar and Outlook event creation and an authenticated ICS download for Apple/iPhone and other calendar applications. Dates are in UTC and clients display their local timezone. Cancellation emails attach an ICS cancellation with the same booking UID and a higher sequence. Calendar copies are not a live subscription; externally created events may need manual updates/removal.

## Free scheduling on Vercel Hobby

`.github/workflows/reminders.yml` runs every five minutes on the default `main` branch and can be run manually in GitHub Actions. GitHub must have Actions enabled for this repository. Scheduled Actions are best-effort: queueing delays, inactivity suspension for public repositories and runner quotas can delay delivery. This is not an exact-second timer.

The workflow requests a short-lived GitHub OIDC token with audience `recitera-class-reminders` and calls `/api/academy/internal/send-mail/`. The backend verifies the RSA signature against GitHub's fixed JWKS endpoint, issuer, audience, token times, exact repository, main branch, workflow identity and schedule/manual event. Forks and pull-request runs cannot trigger this worker. No permanent backend credential or GitHub repository secret is needed. Keep the repository/workflow/domain constants aligned if moving the project.

The existing once-daily Vercel cron remains a fallback using its `CRON_SECRET`; do not replace it with an unsupported frequent Hobby cron. The worker flushes both confirmation emails and due notices. In GitHub, open **Actions → Class reminders and booking notifications** and confirm recent successful scheduled runs (or use **Run workflow**). Check **Django admin → Reminders & cancellation emails** for due/sent timestamps, attempts and sanitized errors. Email service and sender domain must remain configured.
